# webpay 扫码支付能力调研备忘

> 调研日期：2024-12-24
> 调研目标：确认 webpay 现有支付能力是否需要封装以支持扫码支付，以及 memo 格式兼容性

---

## 1. 调研结论

### 1.1 支付能力封装评估

| 评估项 | 结论 | 说明 |
|-------|-----|------|
| 交易创建能力 | ✅ **无需封装** | webpay 已有 `createSPLTransferTransaction` 函数 |
| Memo 支持 | ✅ **已支持** | 与 upnetwork-v2 格式完全一致 |
| 交易签名 | ✅ **已支持** | 通过 Phantom/OKX/Trust 钱包适配器 |
| 交易广播 | ✅ **已支持** | `sendRawTransaction` 函数已实现 |
| 余额检查 | ✅ **已支持** | `usePayment` hook 中已实现 |

**结论：webpay 现有支付能力完全满足扫码支付需求，无需额外封装。只需新增 Payout API 调用逻辑。**

### 1.2 Memo 格式兼容性

| 项目 | Memo 格式 | Program ID |
|-----|----------|------------|
| upnetwork-v2 | `{"webpay":{"orderId":"xxx"}}` | `MemoSq4gqABAXKb96qnH8TysNcWxMyWCqXgDLGmfcHr` |
| webpay | `{"webpay":{"orderId":"xxx"}}` | `MemoSq4gqABAXKb96qnH8TysNcWxMyWCqXgDLGmfcHr` |

**结论：两个项目的 Solana Memo 格式完全一致，webpay 可直接复用。**

export async function createSPLTransferTransaction({

**关键发现：**
1. webpay 已实现 `createMemoInstruction` 私有函数
2. Memo 格式为 `{"webpay":{"orderId":"xxx"}}`
3. 使用标准 Solana Memo Program: `MemoSq4gqABAXKb96qnH8TysNcWxMyWCqXgDLGmfcHr`

### 2.2 upnetwork-v2 支付实现

**文件：** `src/utils/transaction.ts`

```typescript
// 与 webpay 几乎完全相同的实现
function createMemoInstruction(
  memo: string,
  signer: PublicKey,
): TransactionInstruction {
  const encodedData = new TextEncoder().encode(memo);
  return new TransactionInstruction({
    keys: [{pubkey: signer, isSigner: true, isWritable: false}],
    programId: new PublicKey('MemoSq4gqABAXKb96qnH8TysNcWxMyWCqXgDLGmfcHr'),
    data: encodedData as Buffer,
  });
}

// Memo 格式
const memoIx = createMemoInstruction(
  JSON.stringify({
    webpay: {
      orderId,
    },
  }),
  new PublicKey(from),
);
```

### 2.3 扫码支付场景下的 Memo 使用

在 upnetwork-v2 的扫码支付流程中（PayNow/VietQR/PayMongo），存在**两种不同的场景**：

#### 场景 A: ICP 链支付（当前主要使用）
**文件：** `PaymentCardPayMongo.tsx` Line 675-680

```typescript
// ICP 使用简化的 memo 格式
const result = await icrc1TokenTransfer(
  currentUserToken?.address,
  currentPaymentToken?.paymentAddress,
  BigInt(amountUnits),
  `${payoutData?.id || ''};`,  // ← 仅包含 payout ID
);
```

> **注意：** ICP 链的 ICRC-1 memo 限制为 32 字节，因此使用简化格式。

#### 场景 B: Solana 链支付（由后端返回支付地址）
后端 `createPayout` API 返回时会包含 `paymentAddress` 字段，指定 Solana 收款地址。

扫码支付场景下，webpay **只需支持 Solana USDC**，因此：
- 继续使用现有 `{"webpay":{"orderId":"xxx"}}` 格式
- 后端可通过解析交易 memo 关联订单

### 3.3 createSPLTransferTransaction 参数适配

当前签名：
```typescript
createSPLTransferTransaction({
  from: string,
  to: string,
  tokenAmount: string,
  tokenAddress: string,
  orderId: string,  // ← 当前必填
})
```

**建议改动：** 将 `orderId` 改为可选，或新增 `payoutId` 参数，以便区分两种场景：

```typescript
createSPLTransferTransaction({
  from: string,
  to: string,
  tokenAmount: string,
  tokenAddress: string,
  orderId?: string,   // UniWeb 订单场景
  payoutId?: string,  // 扫码支付场景（PayNow/VietQR/PayMongo）
})
```

然后在 memo 中体现：
```typescript
const memoData = orderId
  ? { webpay: { orderId } }
  : { webpay: { payoutId } };
```

> **或者：** 统一使用 `orderId` 字段，后端从 memo 和请求记录两端关联。

## 4. 后端接口确认

### 4.1 createPayout 响应中的 Solana 选项

根据需求，后端会返回 Solana USDC 作为支付选项：

```typescript
interface CreatePayoutResponse {
  id: string;
  // ...
  cryptoCurrency: 'USDC';       // Solana USDC
  cryptoChain: 'SOLANA';        // 链名称
  cryptoAmount: string;         // 需支付的 USDC 数量（最小单位）
  cryptoDecimal: 6;             // USDC 精度
  paymentAddress: string;       // Solana 收款地址
  // ...
}
```

### 4.2 verifyCryptoTransaction 参数说明

```typescript
// 请求
interface VerifyCryptoTransactionParams {
  blockIndex: number;  // 对于 Solana，这里应改为 txSignature
}
```

> **注意：** `blockIndex` 命名来自 ICP 链，对于 Solana 应传入交易签名 (signature)。建议与后端确认参数名称。

## 5. 总结

| 检查项 | 状态 | 备注 |
|-------|-----|------|
| SPL Token 转账 | ✅ 已支持 | `createSPLTransferTransaction` |
| Memo 格式 | ✅ 已兼容 | `{"webpay":{"orderId":"xxx"}}` |
| 钱包签名 | ✅ 已支持 | Phantom/OKX/Trust |
| 交易广播 | ✅ 已支持 | `sendRawTransaction` |
| 余额检查 | ✅ 已支持 | `usePayment.checkBalance` |
| Payout API | ❌ 需新增 | `createPayout`, `verifyCryptoTransaction`, `getPayoutRecord` |
| QR 解析 | ❌ 需新增 | 复制 upnetwork-v2 工具函数 |
| 扫码 UI | ❌ 需新增 | 使用 html5-qrcode 库 |

**最终结论：webpay 现有 Solana 支付能力无需封装，可直接复用。需新增的是 Payout 业务层逻辑和 UI。**
